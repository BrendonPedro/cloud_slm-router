## 0. Three-stage structure (why the experiment is staged)

The full evaluation cannot be one campaign because the three manuscript claims
need different — and increasingly expensive — evidence [S: 03-method-comparison;
architecture/recommended-experiment.md §0]:

| Stage | Tests | Needs | Cost class |
|---|---|---|---|
| **Stage 0** | H1, H2 on *quality-only* labels | released LLMRouterBench scores; CPU | ~zero inference [M] |
| **Stage 1** | H1, H2 for the manuscript's *actual* edge pool (2–4B + diffusion LMs) | GPU to run the real models and build labels | bounded GPU |
| **Stage 2** | H3 + all networked-systems claims (`C` term, `s` term) | edge↔server testbed with a real Split-LLM | testbed + GPU |

Stages gate each other: **if Stage 0 falsifies H1** (a learned router cannot beat
simple baselines on the released pool), the framing changes before any expensive
Split-LLM work is worth doing. **If Stage 0 falsifies H2** (a discriminative
encoder matches the generative Tiny-LM), the "Tiny-LM"/Jacobi framing weakens and
the advisor decision moves toward the N2 calibration axis [S: 03; 04-jacobi-role].
Only work that survives Stage 0/1 justifies Stage 2, which is the stage that makes
the paper a *networked-systems* result rather than an ML-classification result.

## 1. Hypotheses (pre-registered form) [P]

Carried and sharpened from `architecture/recommended-experiment.md §3`, aligned
to the brief-§18 questions H1/H2/H3.

- **H1 — a learned router earns its keep.** On held-out queries, at least one
  learned pre-generation router reaches a strictly better quality/cost frontier
  than *both* (a) TF-IDF + logistic regression and (b) random routing at matched
  call rate. Primary operating point: cloud-call rate at quality ≥ (strong − 1 pt)
  = **CCR@−1**.
- **H2 — the generative Tiny-LM is not dominated by a cheaper encoder.** The
  generative router (candidate A) is *non-inferior* to the discriminative
  micro-encoder (candidate B) on the primary metric **and** offers something B
  does not (better OOD calibration, or better small-label-budget behaviour). If B
  matches A within the CI and A is slower/larger, the Tiny-LM title claim is not
  supported.
- **H3 — the Split action is not reducible to a fixed systems rule.** With a real
  activation-transfer cost and a per-query sensitivity signal, a learned router
  that includes a `SPLIT(d)` action beats the fixed policy
  "sensitive→SPLIT, else cost-optimal". If it does not, H3 collapses to a systems
  policy and the router novelty rests on N2, not N1 [S: 03; 07 §S4].

**Null for each:** the paired-bootstrap 95% CI on the primary-metric difference
includes 0. Nothing below is asserted as true in advance (brief §21).

## 2. Datasets [P] (Stage 0/1) — and why the manuscript's data plan is insufficient as written

- **[M]** The manuscript (L205) assumes SimpleQA routing labels can be read from
  LLMRouterBench. In the released bundle, SimpleQA has records only for 15–17
  flagship/API models; **none** of the manuscript's own weak/strong models appear
  on SimpleQA, and only Meta-Llama-3.1-8B-Instruct appears anywhere in the bundle
  [M; architecture/recommended-experiment.md §1]. **So routing labels for the
  manuscript's pool must be generated by running the models (Stage 1).**
- **Stage 0 primary pool** (binary-scored splits where a weak *and* a strong model
  share the same queries, matched by `origin_query`): `mmlupro/test_1000` (998),
  `gpqa/test` (198), `livecodebench/test` (1055), `livemathbench/test` (121),
  `aime/hybrid` (60) = **2,432 unique queries** [M]. AIME + LiveMathBench are
  reported only pooled (too small alone).
- **Excluded from the primary pool [M]:** `arenahard*` (judge win/tie/loss in
  {0,0.5,1}, not accuracy) — kept only as an optional soft-label secondary.
- **Stage 1 datasets:** SimpleQA (n≈4,326) + the Stage-0 datasets, re-run on the
  manuscript's real edge models (Gemma-3-E2B / Phi-4-mini / the diffusion LMs
  LLaDA·Dream·Fast-dLLM, L271–L290) so the pool matches the paper.
- **Two regimes to keep, because headroom is regime-dependent [M]:**
  - **P-L (nested):** Llama-3.1-8B → qwen3-235b. `weak_better` ≤ 0.08 on every
    split ⇒ routing is "detect the easy queries"; oracle barely exceeds
    always-cloud. Primary metric must be **cloud-call rate at matched quality**,
    not accuracy.
  - **P-Q (complementary):** Qwen3-8B → qwen3-235b. On LiveCodeBench the 8B beats
    235B on 11.3% of queries; oracle 0.755 > 0.677/0.642 ⇒ a router can *raise*
    quality. This regime is where quality-gain (not just cost-saving) is testable
    [S: 06-label-and-training-design; M].

## 3. Label generation [P]

One labelling campaign feeds every training target — this is the key economy from
deliverable 06: targets binary / utility-regression / pairwise-gain / direct-U−λC
/ separated-U all derive from **one** per-(model, query) quality table; only the
loss differs [S: 06 §matrix]. So the A-vs-B-vs-D target ablation is nearly free
once labels exist.

- **Stage 0:** read released per-query scores directly from the bundle; build the
  per-(model, query) score table; derive labels:
  - binary `y = [score_weak ≥ score_strong]`;
  - soft `Δ = score_strong − score_weak` (for utility/pairwise targets);
  - the 4-cell outcome (weak✓/✗ × strong✓/✗) for stratification.
- **Stage 1 (GPU):** run each real edge model and the strong/split model over the
  datasets; score with each dataset's official metric (exact-match / judge /
  unit-test pass as appropriate); **freeze a scoring script per dataset** so labels
  are reproducible. Record raw generations + scores; never hand-edit scores.
- **Cost labels for `C`:** at Stage 0/1 the released `cost` field is provider API
  cost only and says nothing about edge energy or the split link [M]. Real `C`
  (activation bytes, TTFT, energy) is **measured in Stage 2**, not labelled here
  [S: 07 §cost-object].
- **Leakage prevention:** query-string dedup **before** splitting; split files
  (query-hash → split) written to `experiments/prototype/splits/` and hashed
  before any router is trained; test split opened once per final config.

| **A** | Qwen2.5-0.5B-Instruct, LoRA → emits `EDGE`/`CLOUD`; p̂ = softmax of the two label-token logits | 494M [M] | verbalised label + p̂ | A (generative Tiny-LM) — the title concept [S: 02] |

| **B-s** | DeBERTa-v3-small + 1-logit head | (confirm from card) | p̂(weak ≥ strong) | B (micro-encoder), conservative option [S: 03] |
| **B-m** | ModernBERT-base + head | 149.7M [M] | p̂ | B alternative backbone |
| **D** | shared encoder + K per-model utility heads → `Û(M_k,q)`; cost combined outside the net | encoder + small heads | per-model Û | D (structured utility), higher-risk N1 option [S: 02; 07 §S2/S3] |
| **C-pre** | logistic probe on the *weak model's own* prefill hidden state | probe only | p̂ | C (prefill-state), needs 8B forward passes (GPU) [S: 02] |

- **A-J (Jacobi variant of A):** **excluded** from the minimum experiment — the
  router emits one label token, so parallel decoding has nothing to accelerate; it
  enters only if A wins H2 *and* A's output is multi-token [S: 04-jacobi-role;
  06 §Jacobi]. This keeps the sprint honest about the "Jacobi-Forced" title.
- **D vs A/B is the target ablation, not a new backbone:** D shares B's encoder but
  changes the head + loss to model-conditioned utility, which is what makes
  new-model addition cheap (add a head/profile, not retrain the trunk)
  [S: 02 §adaptability; 06 §F].

## 5. Baselines [P]

The brief (§12) requires more than ML routers because the venue is SIGCOMM.

**Simple / ML baselines:** (1) always-edge; (2) always-cloud/always-strong;
(3) random at matched call rate; (4) **TF-IDF (1–2-gram) + logistic regression**
(the "simple baseline" bar); (5) **dataset-prior router** (routes by dataset ID —
an information-leak control showing how much "which benchmark" alone explains);
(6) RouteLLM's released `routellm/bert_gpt4_augmented` applied zero-shot (a
*transfer* baseline, not like-for-like); (7) **oracle** (per-query max, upper
bound).

**Paper baselines (full paper, not minimum):** RouteLLM, Arch-Router (A-zs is its
zero-shot form), RouteLMT (covered in spirit by C-pre), ICL-Router — each verified
against its primary source + code in [S: 01-method-landscape]; fairness caveats:
RouteLLM/Arch-Router are trained on *different* preference labels, so they are
transfer baselines unless re-trained on our labels.

**System baselines (Stage 2, required for SIGCOMM):** lowest-estimated-latency
path; bandwidth-threshold policy; RTT-threshold policy; cost-minimizing rule;
**system-state-only scheduler** (ignores query content — this is the S4 baseline
that isolates the value of *query awareness* over pure systems scheduling)
[S: 07 §S4]. H3 is precisely "learned router > best system-only rule".

## 6. Metrics

### 6.1 Quality / routing metrics (Stage 0/1) [P]
- **Primary:** CCR@−1 (cloud-call rate at quality ≥ strong − 1 pt), dev-tuned
  threshold applied to test; for P-Q also *max test quality over τ*.
- **Curve:** deferral AUC (quality vs cloud-call-rate); RouteLLM APGR and CPT(50%)
  for comparability [S: 01].
- **Calibration:** ECE (15 bins), Brier score of p̂, AURC for the "stay on edge"
  selective decision [S: 05-jev-and-decision-models §calibration].

### 6.2 Networking / systems metrics (Stage 2 — the SIGCOMM core) [P]
Measured on the testbed (deliverable 10), never estimated in this file:
- **Latency:** TTFT, TPOT, end-to-end p50/p95/p99.
- **Communication:** transmitted activation bytes per query, bytes on the
  edge↔server link, split-link volume vs prompt/response volume.
- **Throughput:** requests/sec, tokens/sec at fixed quality.
- **Resource:** GPU util (edge + server), CPU util, memory, energy/power via
  `nvidia-smi` if available.
- **Operational cost:** modelled `C` per route from measured bytes + compute +
  (optional) API price [S: 07 §cost-object].

Each maps to a term of `U − λC`: §6.1 metrics estimate `U`; §6.2 metrics *are* the
measured `C(a,s)` that the router trades against `U` at run time [S: 07].

## 7. SIGCOMM-oriented measurable claims (per brief §13)

For every candidate, the systems claim is stated as IV → DV with a falsifier, so no
claim is asserted true before Stage 2. Representative set [P]:

| Claim | Independent var | Dependent var | Baseline | Measurement | Falsification |
|---|---|---|---|---|---|
| Lower e2e latency at matched quality | router on/off | e2e p50/p95 | always-cloud; system-only rule | testbed timing | router ≥ baseline latency at equal quality |
| Fewer cloud/split invocations at matched quality | router on/off | cloud-call rate | TF-IDF+LR; random@rate | route log | CCR not < baseline (CI incl. 0) |
| Fewer transmitted bytes | route choice | activation+link bytes | always-split at fixed d | byte counter | bytes ≥ always-edge-then-escalate |
| Adapts to changing bandwidth/RTT | swept `s` (tc/netem) | route distribution + e2e latency | fixed-threshold policy | sweep at fixed θ | route dist. invariant to `s` (router ignores network) |
| Better tail latency under contention | injected contention | p99 | system-only scheduler | testbed | p99 not improved |

The bandwidth/RTT-adaptation row is the claim only the **S2** design (learn `U`,
combine with *measured* `C(s)` outside the net) can express: sweeping `s` at fixed
θ produces the latency/byte/cost curves without retraining [S: 07 §S2 — the
finding that λ-in-weights designs *structurally cannot* make this claim].

## 8. Statistics [P]
- **Paired bootstrap** (10,000 resamples, stratified by dataset) for CCR@−1,
  deferral AUC, ECE differences; 95% percentile CIs.
- **McNemar's exact test** at the dev-selected operating point (router vs
  TF-IDF+LR; A vs B) on per-query routed-system correctness.
- **Holm–Bonferroni** across {routers} × {P-L, P-Q} × {in-domain, 4 OOD folds}.
- **5 seeds {0..4}**, mean ± std; a gap < 2×seed-std is not called a win even if the
  CI excludes 0.
- **Power caveat [E]:** at 20% test (~486 pooled), per-dataset CIs are several
  points wide ⇒ per-dataset results are descriptive; only the pooled test is
  confirmatory.

## 9. Splits [P]
- **In-domain:** 60/20/20 train/dev/test, stratified by dataset and by the 4-cell
  outcome; dedup before split; test opened once per final config.
- **OOD (leakage stress):** leave-one-dataset-out over {MMLU-Pro, GPQA,
  LiveCodeBench, math=LiveMathBench∪AIME} — 4 folds. This is mandatory: headroom
  varies strongly by dataset [M], so a router that only learned "which benchmark
  is this" looks strong in-domain and collapses OOD (the mechanism behind
  LLMRouterBench's "routers tie simple baselines" warning) [S: 01].

## 10. Ablations [P]
1. **Label definition:** "weak correct" vs "weak ≥ strong" vs soft `Δ` — the
   cheap cross-target ablation enabled by the single labelling campaign [S: 06].
2. **Router size:** B-s vs B-m; A at 0.5B vs 1.5B (compute permitting).
3. **Input truncation:** 128 vs 512 tokens (an edge-latency lever).
4. **Train-set size:** 10/25/50/100% of train — does the result survive the
   few-hundred-label budget Stage 1 will have per new edge model? (This is the
   adaptability evidence for the "no prohibitive retraining" claim, which the
   brief §D says must not be assumed [S: 00; 02 §adaptability].)
5. **Cost-placement ablation (Stage 2):** S1 (state in the net) vs S2 (measured
   cost outside) vs S3 (separate cost predictor) vs S4 (system-only) — tests
   whether query awareness beats systems scheduling and whether run-time λ/`s`
   sweeping needs S2 [S: 07].
6. **Jacobi (A-J):** excluded unless A wins H2 and emits multi-token output.

## 11. Success / failure criteria (decided before running) [P]

Thresholds carried from `architecture/recommended-experiment.md §9`; they are
**our proposals**, to be confirmed by the advisor before running.

- **Supports H1** iff, for P-L *or* P-Q, the best learned router: (1) CCR@−1 lower
  than TF-IDF+LR by ≥ 5 pts, Holm-adjusted 95% CI excluding 0, pooled in-domain;
  (2) beats random@rate and dataset-prior on deferral AUC in ≥ 3/4 OOD folds;
  (3) ECE ≤ 0.10 in-domain, ≤ 0.15 averaged OOD.
- **Falsifies H1** iff no learned router meets (1), or the dataset-prior router is
  within the CI of the best learned router in-domain while (2) fails → repeats the
  "ties a simple baseline" finding; paper needs a different contribution (N2/N3).
- **Supports H2** iff A is within 2 pts CCR@−1 of the best B (one-sided
  non-inferiority) **and** A wins ≥ 1 pre-declared secondary (OOD ECE or
  train-size@10%). **Falsifies H2** iff B is non-inferior and A has ≥ 3× B's p50
  router latency → the Tiny-LM/Jacobi title claim must be dropped or re-justified.
- **Supports H3 (Stage 2)** iff the learned router with a SPLIT action beats the
  best system-only rule on e2e latency **or** bytes at matched quality, CI
  excluding 0, across ≥ 2 network conditions. **Falsifies H3** iff the fixed
  "sensitive→SPLIT, else cost-optimal" rule is within CI everywhere → H3 reduces to
  a systems policy (N1 precondition fails) [S: 03; 07 §S4].
